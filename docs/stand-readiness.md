# Паспорт стенда для реальной приёмки

Статус на 22.10.2026: фактические значения не предоставлены. Заполняет владелец проекта/администратор вместе с реализатором. Не вставлять пароли, ключи или реальные данные архивов в Git. Нужны только ссылки CredentialRef и обезличенные характеристики.

|---|---|---|

Для одного реального среза можно предоставить один формат первым; оставшийся формат остаётся открытым критерием MVP. Исходная рабочая база не должна становиться объектом изменений spike.

## Следующие этапы

EDT, Vanessa Runner, OneScript, тестовый Git/EDT-проект и их версии нужны перед этапом сборки CF. Корпоративный IdP нужен, если локальный вход запрещён политикой. Выделенный интеграционный CI-runner удобен, но до его выдачи допустим воспроизводимый ручной запуск тестов на стенде.

## Матрица сети

Заполнить host/port/protocol, service principal и фактический результат проверки для направлений: браузер → API; агент → API; агент → SQL/RAS/1С; агент → ArchiveRoot; SQL service → backup staging. Права интерактивного администратора не доказывают права служб. Любой пример адреса/пути в инструкции — пример до внесения в этот паспорт.

## Отчёт spike

Сохранять в docs/spikes/ отдельным PR: паспорт/версии, обезличенные команды и параметры, источник/checksum, перечень созданных ресурсов, результаты подготовки/verify, изоляции/запрета заданий, отрицательные сценарии, удаление и остатки ресурсов. Отдельно перечислить «проверено», «не проверено» и ограничения. Отчёт о симуляции хранится отдельно и не подменяет этот отчёт.

## Готовность пула

До заполнения обязательных полей и успешной проверки выбранного формата пул выключен. После приёмки одного формата включается только подтверждённая capability; пользователь видит, какой формат доступен. Нет численного бюджета, профиля подготовки, прав или изоляции — новые заказы в этом пуле не допускаются.
