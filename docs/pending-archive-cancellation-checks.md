# Приёмка отмены заказа до первой аренды

## Что можно проверить без стенда

Из корня репозитория выполните:

```sh
dotnet restore BuildSystem.slnx --locked-mode
dotnet test BuildSystem.slnx -c Release --no-restore
node --test tests/*.test.cjs
```

Локальный прогон без SQL не проверяет записи и блокировки в базе. Для них используйте GitHub Actions **SQL Server metadata integration** на проверяемом коммите. Этот workflow поднимает одноразовый SQL Server 2022, сохраняет `sql-integration-results` и не проходит, если хотя бы один тест пропущен. Не направляйте интеграционные тесты на стенд или корпоративный SQL Server: они создают и удаляют тестовые базы.

| Что проверять | Где искать |
|---|---|
| Отключённый флаг не меняет заказ; вход, CSRF, членство и точный повтор | [SQL-сценарии отмены](../tests/BuildSystem.IntegrationTests/SqlPendingArchiveCancellationTests.cs), [HTTP-контракт](../tests/BuildSystem.ApiTests/PendingArchiveCancellationApiTests.cs) |
| Отмена и первая аренда не могут обе победить; ошибка до commit откатывает переход | [SQL-сценарии отмены](../tests/BuildSystem.IntegrationTests/SqlPendingArchiveCancellationTests.cs) |
| Подтверждённые отмены видны в нужной области; противоречия исключены до пагинации; отчёты агента не возобновляют отменённый заказ | [SQL-сценарии списка и stage](../tests/BuildSystem.IntegrationTests/SqlStageOperationsTests.cs) |
| История отключённого проекта по-прежнему доступна владельцу с членством, но не подтверждает противоречивую отмену | [SQL-сценарии истории](../tests/BuildSystem.IntegrationTests/EnvironmentOrderSummaryTests.cs) |
| Панель сверяет список с деталями, не запускает отмену и не выдаёт логический резерв за свободное место | [Браузерные сценарии stage](../tests/stage-ui.test.cjs) |

## Что нужно согласовать для проверки на стенде

До любых действий администратор подтверждает конкретный изолированный контур и проект, тестового владельца и пул, версию базы метаданных с уровнем совместимости не ниже 130, допустимый тестовый архив и окно проверки. Нужны отдельное разрешение на применение миграции и согласование, кто и на какой срок включает `PendingArchiveCancellation:Enabled`. Паспорт и более широкие требования к контуру — в [готовности стенда](stand-readiness.md). Этот документ не даёт разрешения на включение и не описывает приёмку реального восстановления 1С.

Критерии будущей проверки: у намеренно не выданного агенту заказа отмена и авторизованный повтор дают один результат; фильтр «Отменённые» показывает ту же операцию; stage подтверждает логическое освобождение, а cleanup не выдаёт запись об удалении. У отдельного заказа с уже выданной первой арендой отмена даёт конфликт и не освобождает резерв. Для SQL-аудита сверяются идентификаторы заказа, актор и время UTC. В отчёт не включаются cookie, токены, внутренние пути и фактические данные архивов.

После согласованной проверки запись об уже выполненной отмене сохраняется. Выключение команды не восстанавливает отменённые заказы и не убирает их из истории. Не удаляйте квитанции или аудит и не переигрывайте отмену правкой состояний в БД.
