## Реализация и ограничения

Отдельная additive metadata table с Restrict RestoreIntent FK, unique RestoreIntent anchor и attempt identity, revision CAS, checks state/reason/attempt pairing и immutable identity guard. Никаких обновлений существующих snapshots/holds/env lifecycle, новых grants или target commands. Register/current validation в той же Serializable transaction, global agent-control → relational root → pool locks. Existing RestoreIntent сохраняет canonical uniqueness. Это координация server ledger, не physical target lock и не внешнее ownership evidence.

Current admin проверяется по actualIdentityrole до replay. Register/Begin проверяют enabled project/root/pool, assigned approvedagent/scope/membership, stagecompleted/leasecompleted/exact artifact/retained immutable snapshot/canonicalmapping, отсутствие activelease/retirement/cleanup/release. Quarantine требует admin identity и существующую корректную operation, но не повторяет отменённый admission. Все изменения audit атомарны с row transitions.

Feature default-off; application/internal DI только. API host не получает routes, worker не получает dispatch. Нет deployment или metadata migrations на стенде в этом этапе. Миграция применяется только к disposable SQL fixtures в tests/CI. Перед любым production migration отдельный review/backup; Down destructive и не normalrollback.

Этот ledger не fresh executable authority: нет expiry/lease issuance/reassignment, physical alias identity/exclusion, trusted owned-empty-target assertion или actual creation/restore. Будущий executable срез требует отдельного согласования и тестов crash boundaries. Scheduled-jobs deny before/after/afterrestart mandatory; security profile не mandatory.

## Transport uncertainty и retries

Receipt для всех трёх методов полностью строится и валидируется до commit. Это не гарантирует доставку ответа: ошибка/потеря ACK после SQL commit не означает rollback. Register и BeginAttempt повторно проверяют current authorization/bindings и используют durable replay identity; exact BeginAttempt replay возвращает false даже после quarantine. Quarantine намеренно не имеет внешней idempotency key: новая или execution-strategy повторная попытка после уже committed quarantine может вернуть RevisionConflict. Это не доказывает отсутствие quarantine. Повторный вызов не меняет terminal state и не разрешает reset/new attempt/release. Для диагностики добавлен внутренний ITargetCreationOperationReads.GetAsync по OperationId: current DB Administrator, Serializable metadata lookup, structural pins validation; NewlyRecorded всегда false. Enabled требуется как и для записей. Текущее admission не проверяется: отключение project/pool/root, agent или owner membership не прячет durable operation от действующего admin. Нет SaveChanges/audit/state mutation или обращения к physical target. Это историческая metadata snapshot, не fresh authority, proof of side effect, rollback или success. Публичного read endpoint/worker consumer в текущем срезе нет. Missing404 означает только отсутствие по ID в текущем ledger; не отсутствие physical target. Тестовый post-commit interceptor моделирует TimeoutException ПОСЛЕ возврата actual SQL CommitAsync: commit не подавляется и не откатывается. Это deterministic simulated ACK loss, не реальный network disconnect/SQL failover/process crash. SQL Server native execution strategy (без production hooks) повторяет delegate. Success-verification для quarantine не добавляется; ожидается RevisionConflict после durable terminal commit, без reset/reissue.
