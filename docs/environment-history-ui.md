# Доступные окружения: read-only история

На существующей странице `/stage` добавлена отдельная панель «Мои окружения». Только явная кнопка обновления после проверки пользовательского сеанса выполняет GET `/api/test-environments`; кнопка сведений выполняет GET `/api/test-environments/{id}`. Все данные защищены существующей cookie-auth API авторизацией. Новых server endpoints, lifecycle transitions, TTL/quota policy, migration, CREATE/restore/grants не вводится.

## Видимость и смысл

Обычный пользователь видит свои окружения только при текущем членстве в проекте. Администратор видит все доступные по существующей политике записи: заголовок не должен пониматься как фильтр owner для администратора. Панель выводит реальные server metadata: ID окружения и проекта, displayName, state, expiresAt. State отображается буквально, без вычисления физической готовности, подключения или Ready по косвенным признакам. Это история окружений, не новый collection API запросов: requestId/jobId и полный журнал заказов список окружений не предоставляет.

Можно вернуться к принятому окружению после перезагрузки страницы или утраты квитанции. Список не восстанавливает утраченный idempotency key, не отменяет неопределённый заказ и не гарантирует однозначное сопоставление одинаковых имён. При неопределённом ответе создания существующий retry того же запроса сохраняет прежнюю семантику. Просмотр истории сам ничего не создаёт и не повторяет.

## Границы чтения

Существующий API списка не имеет pagination/limit и возвращает полную доступную коллекцию. UI валидирует весь полученный массив и дубликаты, отображает максимум первые 200 записей и явно сообщает полное количество и отсутствие постраничного просмотра. Это ограничение DOM, НЕ ограничение server query или сетевого размера. Для большого парка потребуется отдельный paged API; текущий срез не имитирует его.

Запросы same-origin, no-store, redirect:error, без фонового polling. Значения выводятся через textContent. Проверяются непустые UUID, допустимые ограниченные имена/состояния и nullable дата; ответ сведений обязан совпадать по ID окружения и проекта со строкой. Список и сведения являются отдельными снимками: изменения state/expiry допустимы, идентификатор проекта не подменяется.

## Сеансы и устаревшие ответы

У списка/сведений свои AbortController и поколения. Новый refresh очищает сведения; другой выбор отменяет предыдущее чтение; поздние transport/body ответы не заполняют интерфейс. 401/403 из новых чтений скрывают workspace через существующий login/reset путь. Навигация основного списка и смена сеанса очищают панель. Pagehide/pageshow и скрытие вкладки очищают только новую history-панель и не трогают order intent, его ключ или retry. Автоматического чтения после восстановления вкладки нет; повторите явное обновление.

Нет browser storage, секретов, ссылок подключения, кнопок продления/удаления/отмены/запуска. Logout и защищённые чтения по-прежнему независимы от agent bearer endpoints. Неверный или недоступный ответ очищает соответствующий результат, не подменяется Ready или пустой успешной историей.

## Проверки

Новые browser VM fixtures проверяют protected GET, явное обновление, empty/cap200, text-only XSS rendering, ID correlation, invalid responses, latest-generation, auth/logout/navigation/hidden clearing без POST. API fixtures используют реальную cookie authentication с read-only stub: user/admin Actor, exact metadata schema, anonymous/Bearer-only401, missing/invalid404, no-store/nosniff, no CSRF for GET. Два disposable SQL tests проверяют скрытие списка/environment/request после удаления текущего project membership и доступ администратора к чужому окружению без членства, сохраняя существующую политику.

Локальный targeted: API6passed, SQL2explicitlyskipped (нет opt-in disposable database), Stage/history Node54passed включая12newhistory cases. Baseline fake DOM дополнен document.addEventListener без ослабления production handlers. Полный локальный Release: 2413passed/0failed,272SQLexplicitlyskipped. Node:73passed/0failed.
