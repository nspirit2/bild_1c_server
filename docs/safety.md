# Безопасность, ошибки и восстановление

## Последовательность обновления существующей базы
Preflight -> Artifact Verification -> Backup -> Backup Verification -> Lock New Sessions -> Quiesce Existing Sessions -> LoadCfg -> UpdateDBCfg -> Verify -> Unlock (только при безопасном состоянии).

Полная загрузка CF — потенциально разрушающая операция. Перед запуском проверяются права пользователя, допустимость целевой базы (MVP: только тестовые), отсутствие активного изменяющего задания, совместимость конфигурации, целостность артефакта, доступность backup. Изменения базы вне Git требуют явного решения.

## Критичные сценарии
- Ошибка backup: остановить pipeline до загрузки CF.
- Ошибка LoadCfg/UpdateDBCfg: состояние NeedsAttention, никакого слепого retry.
- Потеря связи с агентом: lease истёк, но процесс мог продолжать работу; сверить состояние до новой выдачи.
- Неуспешная проверка после развёртывания: оставить базу в MaintenanceRequired и не снимать блокировку.
- Ошибка cleanup: задание reconciliation, уведомление оператора.

## SQL
BACKUP DATABASE и RESTORE VERIFYONLY исполняются на SQL Server, путь резервной копии относится к серверу СУБД. VERIFYONLY не заменяет тестовое восстановление. Автоматический SQL RESTORE в MVP не предусмотрен.

## Защита
Секреты вне YAML, аргументов в логах и outputs; HTTPS, авторизация пользователей и агентов, allowlist операций CLI, проверка всех путей, аудит всех изменений, отдельные сервисные учётные записи с минимальными правами.
