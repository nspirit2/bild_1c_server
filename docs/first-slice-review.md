# Первый инженерный срез — границы ревью

## Назначение

Чистая доменная модель будущего заказа тестовых баз. Ни создание инфраструктуры, ни сквозной пользовательский сценарий этим срезом не принимаются. Ветка: `feat/domain-foundation`.

## Проверяемые правила

- Допустимые переходы жизненного цикла и отказ от прямой установки Ready.
- Структурированная проверка текущей попытки, источника, версии конфигурации, профиля, изоляции и доступа.
- TTL от публикации Ready; повторная проверка не продлевает срок автоматически.
- Продление от текущего времени, согласование с expiration/delete через expected version.
- Удаление только с подтверждённой историей владения и установленным исходом внешних операций.
- Освобождение квоты только после подтверждённого отсутствия SQL БД и регистрации ИБ.
- Failed, Expired, Deleting и NeedsAttention продолжают занимать объём/количество.
- Незавершённая внешняя операция удерживает слот параллельного создания независимо от пользовательского состояния окружения.
- Пулы с незаданными бюджетами не допускают заказов.

## Замечания независимого ревью

В ходе read-only ревью выявлены два сценария. В модели внесены исправления и добавлены проходящие регрессионные проверки:

1. Повтор удаления после NeedsAttention должен привязать новую попытку к новому заданию и отклонять подтверждение предыдущего задания.
2. Переход создания в NeedsAttention не должен освобождать слот параллелизма, пока внешний RESTORE может выполняться. Снимку квот нужны данные об установленном исходе операции, а не только статус окружения.

## Не является доказательством интеграции

Свидетельства в unit-тестах синтетические. Их реальность, полнота журнала, актуальность lease, права пользователя, отмена, rowversion, идемпотентность HTTP и сериализация конкурентных квот должны проверяться будущим серверным слоем и интеграционными тестами. Доменная библиотека не является границей доверия для JSON клиента.

SQL Server, 1С, UNC, DPAPI, Windows-службы и реальная сетевая изоляция в этом срезе не запускались. Выполнение GitHub Actions на Windows подтверждается только отчётом удалённого workflow, а не локальной Linux-сборкой.
