# ProcessRunner foundation

.NET 10 library; no Worker, shell, real 1C, or provider dependency. The host constructs an immutable snapshot of operator-owned trusted tool IDs and absolute executable paths and explicit existing workspace roots. Providers resolve job workspaces, but the runner independently validates absolute containment and rejects symlink/junction/reparse ancestors. Keep roots and tool installations ACL-protected: checks are not an OS sandbox and cannot prevent concurrent privileged filesystem replacement. Executable aliases/symlinks are operator trust; do not configure interpreters, shell wrappers, or untrusted executables. Common shell executable names are rejected. Argument semantics are the trusted provider's responsibility (allowlisting dotnet, for example, does not make arbitrary DLL arguments safe).

`ProcessCommand` carries typed arguments, bounded timeout `(0, 24h]`, and optional literal known secrets. Sensitive argument values are automatically added to redaction. Arguments use `ArgumentList`, never shell interpolation. No arguments, raw process exceptions, executable paths, environment values, or secret values are recorded in results/exceptions. Sensitive values necessarily reach the child process and may be visible through OS process inspection: prefer a provider-supported protected channel for credentials when available.

Environment inheritance is off by default. Configuration can opt into explicit benign names only (SystemRoot/WINDIR, temp/home directories, LANG/LC_*, TZ); loader, startup-hook, PATH and arbitrary per-command environment injection are unavailable. Some tools need explicit server-controlled temp/home setup and may not work in the minimal environment.

Both UTF-8 streams are consumed concurrently with ordering within each stream, not between streams. Callbacks are serialized. Literal secret filtering precedes newline/chunk splitting and works across read boundaries and embedded newlines. Lines longer than `MaxLineCharacters` become bounded fragments; `MaxOutputCharacters` is a combined callback character budget and `OutputTruncated` marks dropped output. Reads continue/discard at the budget; output is never accumulated in the result. Known-secret count/length, buffers and logging are bounded. This is exact literal masking, NOT proof against encodings, transformations, partial secrets, secrets split between streams, or unknown credentials. Providers must avoid emitting secrets in the first place.

Timeout/caller cancellation returns an explicit state with PID and observed exit code, after tree-kill and direct-process wait. Callback failures kill and await, then throw `ProcessRunnerException` with `callback_failed` and no original exception. Callback waits share timeout/cancellation; a noncooperative user callback task may continue after the runner returns, so callbacks must not own process lifetime or retain unsafe raw data. Other stable codes are `invalid_command`, `start_failed`, `output_failed`, `process_failed`, and `termination_failed`; constructor policy errors have fixed diagnostic messages.

`Process.Kill(entireProcessTree: true)` is best-effort OS tree enumeration, not containment. Children that detach/reparent or outlive a parent that already exited may escape; direct-parent wait does not guarantee every descendant has been reaped. Production stronger containment needs Windows Job Objects / Linux cgroups and reconciliation. Linux test treats zombie as terminated, not executing. A process exit code alone never establishes an external operation's success or rollback. There is no real 1C integration here.

Run isolated tests with `/root/.dotnet/dotnet test tests/BuildSystem.ProcessTests/BuildSystem.ProcessTests.csproj`. Fixture is a console executable started through an absolute, allowlisted dotnet host. Linux is tested locally; Windows compatibility is prepared in tests, not locally verified.
